# 06 · 运行方式

> 一句话摘要：要什么环境、怎么装、有哪些命令和入口、运行时依赖哪些环境变量与落盘位置。

## 环境要求

| 项 | 要求 | 原因 |
|---|---|---|
| Node | **≥ 24** | 靠 Node 的 type stripping 免构建**直接执行 `.ts`**；版本不足时入口首行即报错退出 |
| 浏览器 | Firefox | 由 Playwright 管理，不依赖系统里装的火狐 |
| 平台 | Windows 为主要目标 | explorer 代启 keeper 的路线仅 Windows 可用；其他平台走常规 spawn |

## 安装

```
cd dskts
npm install                    # 唯一的运行时依赖是 playwright
npx playwright install firefox # 下载 Playwright 版 Firefox
```

可选：把 `dskts/bin/` 下的 `dsk`、`dsk.cmd`、`dskts-launch.mjs` 复制到 `~/.qoder-cn/bin/`，就能用 `dsk` 这个名字调用（这一步即「命令名移交」，见根 [README.md](file:///d:/G/github/实用工具/DeepSeek命令行/README.md) 的待办）。

## 命令全表

| 命令 | 作用 |
|---|---|
| `dskts "问题"` | 默认接在本 Agent 的连续会话里提问；stdout 只有答案 |
| `dskts`（不给参数） | 从标准输入读问题，例如 `echo 问题 \| dskts` |
| `dskts --chat 关键词 "问题"` | 指定续问的会话；命中不唯一时退 2 并列出候选 |
| `dskts --out 文件 "问题"` | 答案同时落盘（与 stdout 逐字一致） |
| `dskts --file 附件 "问题"` | 挂附件，可重复；类型白名单以页面 `input[accept]` 为准 |
| `dskts --stream "问题"` | 边生成边打印（按拍增量输出，结束后与整段模式一致） |
| `dskts --max-wait 秒 "问题"` | 等待总上限，默认 240，封顶 3600 |
| `dskts --mark 名字 "问题"` | 强制本次的归属标记，盖过自动识别 |
| `dskts up` | 起实例；未登录则在窗口里登录一次（登录态常驻） |
| `dskts down` | 关实例并**删除 profile 目录**（含全部登录态） |
| `dskts status` | 看实例 / 登录态 / 目录状态 |
| `dskts whoami` | 看这次会被记成哪个 Agent，以及依据 |
| `dskts chats` | 列出会话，每条标出归属（本 Agent 行首带 `*`） |
| `dskts rm 关键词或会话id` | 删除会话；默认只演练，`--yes` 真删，`--any` 越过前缀白名单 |
| `dskts -h` / `--help` | 用法 |

**退出码**：`0` 成功 / `1` 运行错误（含用法错、超时截断）/ `2` 前提不满足。语义细节见 [05-协议与接口契约](./05-协议与接口契约.md)。

## 入口链

```
dsk.cmd（cmd / PowerShell）─┐
                            ├─> node dskts-launch.mjs ─> import ../src/dskts.ts
dsk（Git Bash）             ─┘
```

`dskts-launch.mjs` 是一个**ASCII 转发桩**，定位真身的顺序是：环境变量 `DSKTS_REAL` → 自身相邻的 `../src/dskts.ts`。

**为什么需要这个桩**：`cmd.exe` 按 OEM 代码页解析 `.cmd` 文件，路径里带中文（本仓库就带）会乱码。所以放在 PATH 上的入口文件名与内容必须是纯 ASCII，由 Node 按 UTF-8 去加载真正的中文路径。

## 环境变量

| 变量 | 作用方 | 用途 |
|---|---|---|
| `DSK_AGENT` | CLI | 调用方自己声明身份，优先级仅次于 `--mark` |
| `DSKTS_REAL` | 转发桩 | 桩被装到别处时，指向真身 `dskts.ts` |
| `DSKTS_NO_EXPLORER` | CLI | 设为 `1` 禁用 explorer 代启 keeper，改走常规 spawn |
| `DSK_LOG_STDIO` | keeper | 由 `env.ts` 拉起 keeper 时注入，告知「stderr 已指向日志文件」，避免重复写 |

## 落盘位置

全部落在 `%LOCALAPPDATA%` 下。

| 东西 | 路径 | 谁建 | 谁删 |
|---|---|---|---|
| 浏览器 profile | `%LOCALAPPDATA%\dsk-ffprofile\` | keeper（`launchPersistentContext`） | `dskts down` 整目录删除 |
| 锁文件 | `%LOCALAPPDATA%\dsk-ffprofile.lock` | keeper 监听成功后写（含 PID 与启动时间） | `down`；或下次起手发现是死 PID 时接管 |
| token 文件 | `%LOCALAPPDATA%\dsk-ffprofile.token` | keeper 每次启动生成并写入 | 随 profile 目录一起删 |
| 日志文件 | `%LOCALAPPDATA%\dsk-ffprofile.log` | keeper 追加写入 | 超过上限时轮转为 `.log.1`（仅在 keeper 自行落盘的模式下生效）；不自动清理 |
| keeper 引导目录 | `%LOCALAPPDATA%\dsk-keeper-boot\` | `env.ts` 的 explorer 代启路线 | 不自动清理（内容为可再生的引导文件） |

profile 目录里有完整登录态，所以它是**唯一需要刻意保护的对象**：`down` 会连它带 `.lock`/`.token`/`.log` 一并处理。

## 典型工作流

```
dskts up              # 首次：起实例，在弹出的窗口里登录一次
dskts "帮我写个正则"    # 之后反复提问，走热连接
dskts status          # 想看状态时
dskts down            # 收摊：关浏览器并删掉登录态
```

说明两点：

- **登录态常驻**，不必每次 `up`；只有 `down` 之后才需要重新登录。
- **keeper 不是服务**：没有开机自启，由 `up` 显式拉起、`down` 显式关闭；窗口关掉即停。
