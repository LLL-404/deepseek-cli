# 03 · 模块职责与依赖

> 一句话摘要：`src/` 十个文件各自站在哪一层、只该知道什么、依赖谁、改它会牵动谁。

## 逐文件卡片

每张卡片回答五个问题：职责 / 只该知道 / 不该知道 / 依赖谁 / 改它牵动谁。

### constants.ts

- **职责**：登记正文容器与横幅选择器、停止按钮判据、开关标签（中英双语变体）、等待判定参数、keeper 端口、profile 目录名、附件结算上限、三档退出码。
- **只该知道**：这些常量本身。
- **不该知道**：任何流程、任何 DOM 之外的结构。
- **依赖谁**：无（纯常量，零 import）。
- **改它牵动谁**：选择器改动牵动 [pageops.ts](file:///d:/G/github/实用工具/DeepSeek命令行/dskts/src/pageops.ts) 与 [tools/](file:///d:/G/github/实用工具/DeepSeek命令行/dskts/tools) 下的诊断器；退出码改动牵动 [dskts.ts](file:///d:/G/github/实用工具/DeepSeek命令行/dskts/src/dskts.ts) 的映射。**注意**：[gate.ts](file:///d:/G/github/实用工具/DeepSeek命令行/dskts/tools/gate.ts) 与 [probe_prime.ts](file:///d:/G/github/实用工具/DeepSeek命令行/dskts/tools/probe_prime.ts) 各自带了一份选择器与 profile 目录名的副本，改这些常量时要一并同步。

### frame.ts

- **职责**：`encodeFrame` 把对象编成「4 字节大端长度 + JSON」；`createFrameDecoder` 流式解码并按帧回调；`rpc` 做一连接一命令的客户端封装；`FrameError` 标记解码层错误；`FRAME_MAX_BYTES` 立上限。
- **只该知道**：TCP 字节流与 JSON。
- **不该知道**：具体命令的语义、页面、进程管理。
- **依赖谁**：仅 `node:net` 的类型。
- **改它牵动谁**：CLI 与 keeper **两端同时**——这是双向协议。

### env.ts

- **职责**：路径函数（`localRoot` / `profileDir` / `lockPath` / `logPath` / `tokenPath` / `bootDir`）；锁的读写与 `pidAlive`；token 的读写；`ensureKeeper` 拉起并等待 keeper；`launchKeeperViaExplorer` / `spawnKeeperDirect` 两条启动路线；`sweepStale` / `killStaleByProfileName` 残留清扫；`downFallback` / `deleteProfileDir` 兜底清理。
- **只该知道**：进程与文件系统。
- **不该知道**：DOM、选择器、命令语义。
- **依赖谁**：[constants.ts](file:///d:/G/github/实用工具/DeepSeek命令行/dskts/src/constants.ts)（profile 目录名）、[client.ts](file:///d:/G/github/实用工具/DeepSeek命令行/dskts/src/client.ts)（探活）、[sweep.ps1](file:///d:/G/github/实用工具/DeepSeek命令行/dskts/src/sweep.ps1)（进程清扫）。
- **改它牵动谁**：keeper 的启动方式与 `down` 的清理范围；改错会留下残留进程或删不干净。

### client.ts

- **职责**：`tryConnect` 带超时地探测 keeper 是否在监听；再导出 `rpc` 与 `FrameResp` 类型，作为 CLI 侧的统一入口。
- **只该知道**：端口与连接。
- **不该知道**：命令、页面。
- **依赖谁**：`constants.ts`、`frame.ts`。
- **改它牵动谁**：所有需要连 keeper 的路径（`dskts.ts` 与 `env.ts`）。

### judge.ts

- **职责**：`createJudge` 返回一个只有 `tick(reading)` 的状态机。内部实现落地认法、双信号判定、读数抖动容忍、上限收摊。
- **只该知道**：`Sample` / `Reading` 与 `JudgeConfig`。
- **不该知道**：**任何 IO**——不碰页面、不碰进程、不碰文件。这正是它能被离线测试的原因。
- **依赖谁**：无（零 import）。
- **改它牵动谁**：判定行为的全部；同时牵动 [judge.test.ts](file:///d:/G/github/实用工具/DeepSeek命令行/dskts/tests/judge.test.ts) 的 14 项用例。

### pageops.ts

- **职责**：读数器 `readOnce`；侧栏 `convAnchors` / `convAnchorsWait`；开关 `setToggles`；会话选择 `selectSession`；填题 `fillAndVerify`；前提校验 `guardNotBusy`；提交 `submitWithVerify`；附件 `attachFile`；改名 `renameTo`；删除 `rmConversation`；判定循环 `judgeLoop` 与 `makeJudge`；诊断 `probeRead`；错误类型 `FlowError`。
- **只该知道**：Playwright API 与 DOM。
- **不该知道**：命令行、进程管理。
- **依赖谁**：`constants.ts`、`agent.ts`（归属判定）、`judge.ts`（判定）。
- **改它牵动谁**：全部页面交互行为；页面改版时首当其冲。

### askflow.ts

- **职责**：`askFlow` 把一次提问排成明确顺序——导航 → 选会话 → 开关 → 附件 → 填题 → 前提校验 → 取快照 → 提交 → 判定 → 改名，并在 `noRender` 时刷新重取一次。
- **只该知道**：流程顺序。
- **不该知道**：命令行参数解析、进程管理——它只接收已解析好的 `AskParams`。
- **依赖谁**：`pageops.ts`、`agent.ts`、`constants.ts`。
- **改它牵动谁**：一次提问的全部行为。

> 注：原始设计曾把「编排」放在 CLI 侧，实际实现落在 keeper 侧（进程层）——因为只有 keeper 持有 `Page` 与判定状态。这是一处**已记录的职责偏离**。

### agent.ts

- **职责**：`RULES` 识别表、`detectAgent` 两轮扫描、`resolveMark` 三级优先级、`normalizeName` / `toMark` 命名规范化、`ownerOf` / `isOwned` / `ownedPrefixes` 归属判定、`homeTitleFor` 连续会话标题、`LEGACY_PREFIXES` 历史前缀。
- **只该知道**：环境变量与命名规则。
- **不该知道**：页面、进程、DOM。
- **依赖谁**：无（纯逻辑，零 import）。
- **改它牵动谁**：会话归属显示、`rm` 的白名单范围、新建会话的命名。

### keeper.ts

- **职责**：常驻进程本体。持有 Playwright persistent context；生成并校验会话 token；校验帧形状与原型链；用 `busy` 串行化命令；`handlers` 表分发命令；日志与轮转；`[dying]` 退出埋点。
- **只该知道**：帧协议、Playwright、页面层操作。
- **不该知道**：命令行参数、**Agent 识别**——那是 CLI 侧的事，mark 随帧传进来。
- **依赖谁**：`playwright`、`constants.ts`、`env.ts`、`frame.ts`、`agent.ts`、`askflow.ts`、`pageops.ts`。
- **改它牵动谁**：协议面与全部命令行为。

### dskts.ts

- **职责**：Node 版本门禁；`parseArgs` 手写解析；六个子命令实现；`describeMark` 归属说明；`readStdinQuestion` 读管道；`startTail` 转发 keeper 日志；`call` / `rpc` 收发帧；三流与退出码。
- **只该知道**：参数、帧、退出码。
- **不该知道**：DOM、选择器、Playwright。
- **依赖谁**：`constants.ts`、`agent.ts`、`env.ts`、`client.ts`，以及 `frame.ts` / `askflow.ts` 的类型。
- **改它牵动谁**：CLI 面与退出码契约。

## 模块依赖图

```
dskts.ts    →  agent.ts ｜ env.ts ｜ client.ts
env.ts      →  client.ts ｜ constants.ts
client.ts   →  frame.ts ｜ constants.ts
keeper.ts   →  askflow.ts ｜ pageops.ts ｜ agent.ts ｜ env.ts ｜ frame.ts ｜ constants.ts
askflow.ts  →  pageops.ts ｜ agent.ts ｜ constants.ts
pageops.ts  →  judge.ts ｜ agent.ts ｜ constants.ts
constants.ts → （无）
frame.ts    →  （无内部依赖，只用 node:net 的类型）
judge.ts    →  （无）
agent.ts    →  （无）
```

**依赖方向的两条纪律**：

1. **纯逻辑在最底层，没有出边**——`judge.ts` 与 `agent.ts` 都是零 import，因此可以脱离浏览器与进程单独测试。
2. **页面层不碰进程，编排层不直接写 JS**——`pageops.ts` 只管选择器与 Playwright，`askflow.ts` 只管顺序，`keeper.ts` 只管进程与协议。

## 外部依赖

| 依赖 | 类型 | 用途 |
|---|---|---|
| `playwright` | 运行时（唯一） | 浏览器驱动：`launchPersistentContext`、`Page` API |
| `typescript` | 开发 | 类型检查（`tsc --noEmit`） |
| `@types/node` | 开发 | Node 类型定义 |

没有构建步骤：运行依赖 Node ≥ 24 的 type stripping 直接执行 `.ts`。
