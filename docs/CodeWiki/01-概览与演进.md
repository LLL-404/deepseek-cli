# 01 · 概览与演进

> 一句话摘要：这个项目是什么、要解决什么问题、怎样算成功，以及它是怎么走到今天这个形态的。

## 它是什么

`dskts` 是一个命令行工具：把一句话丢给 **DeepSeek 网页版**，把完整答案取回 **stdout**，把过程日志打到 **stderr**。答案可以直接进管道、被脚本或其他 Agent 调用。

它自动化的是**你自己已登录的网页界面**，而不是官方 API——代码里没有 API key，也不需要付费账号。

## 要解决的问题

| 约束 | 含义 |
|---|---|
| 不想走官方 API | 本机没有 API key，开放平台还要另外充值计费 |
| 不想新建账号 | 复用现有网页版登录态 |
| 不能撞图形人机验证 | 任何需要人工过验证码的路线都排除 |
| 要能进管道 | 答案必须是干净的正文，不能混进日志或页面杂项 |
| 不干扰日常使用 | 不能占用或关闭你正在用的浏览器窗口 |

## 成功判据

项目给自己定了五条可检验的标准：

1. **stdout 只有答案本身**——不含思考独白、不含代码块横幅、不含页面其他文字。
2. **退出码能分流**——成功为 0，运行错误为 1（含超时截断、页面无渲染、提交失败），前提不满足为 2；发生截断时会在 stderr 额外给出警告。
3. **会话可连续**——能反复接在同一条会话里保持上下文，也能指定接到哪条会话后面。
4. **凭据可控**——登录态存放在独立 profile，`dskts down` 时整个目录删除。
5. **不碰你正在用的浏览器**——使用独立 profile，不干扰日常窗口。

## 明确不做

- **不伪造反爬令牌**（如 `bf`、`dltk`）。
- **不在浏览器之外重放会话凭据**——观测页面自己发出的行为可以，替页面签名不行。
- **不做多站点抽象**——只服务 DeepSeek 网页版，不为第二个站点预留结构。
- **不做并发**——一次只允许一条自动化连接，后来的调用退 2 不排队。
- **不发布为包**——`package.json` 标了 `private`，不做分发。

其中「不伪造反爬令牌」与「不在浏览器之外重放会话凭据」两条同时是安全边界，它们的由来与代价见 [08-安全模型与失败处理](./08-安全模型与失败处理.md)。

## 演进沿革

| 时间 | 事件 |
|---|---|
| 最初 | 手写 Marionette 协议（Firefox 的自动化远程控制协议）的 **Python 单文件实现**（命令名 `dsk`），零第三方依赖 |
| 2026-10-06 | 经四阶段规划与 Gate 风控验证，迁移为 TypeScript + Playwright + 常驻 keeper（过渡命令名 `dskts`） |
| 2026-10-07 | 旧 Python 版代码与它的设计文档被移除，`dskts` 成为**唯一实现** |
| 2026-10-07 | `dsk` 命令名移交完成：入口桩（`dsk` / `dsk.cmd` / `dskts-launch.mjs`）装到 `~/.qoder-cn/bin/`，PATH 上可直接用 `dsk` 调用 |

当前形态引出的一个直接后果：**不再有后备实现**。原先保留 Python 版是为了在 dskts 出问题时留退路；现在 dskts 是唯一路径，它的软肋（见 [09-验证体系与技术债](./09-验证体系与技术债.md)）就是整个工具的软肋。
