## 二、建议执行顺序

```
M1（骨架）
  └─> M2（速读三章）      ← 先做这里：若速读路径立不住，后面全白写
        ├─> M3（结构细节三章）
        └─> M4（横切三章）  ← 与 M3 无依赖，可并行
              └─> M5（校验与汇总）
```

**排序理由**
1. **M2 先于 M3/M4**：概览与架构是全篇的地基，其余章节都引用它；地基不对，细节写得越多越难改。
2. **M3 与 M4 可并行**：M4 的三章是横切主题（决策、安全、验证），只依赖架构章，不依赖模块卡片。
3. **M5 集中做**：可定位性与一致性校验需要全篇存在才有意义；分散做会重复劳动。
4. **T1.1 索引最后回填**：骨架期先建空表，M2 完成后再把每章的真实摘要回填，避免索引与正文不一致。

## 三、关键路径与风险

**关键路径**：T1.2 → T2.2 → T3.1 → T3.2 → T5.2

**执行期需盯的风险**（承接 Phase 3 第五节）：
- T3.1/T3.2 体量最大，最容易滑向「复述源码」——守住「只写结构与边界，不复述实现」。
- T2.2 的时序章最容易写成流水账——按「分步 + 每步的失败条件」组织，而非按代码顺序。
- T5.2 一致性抽查若发现偏差，回退到对应章节而非就地打补丁。
