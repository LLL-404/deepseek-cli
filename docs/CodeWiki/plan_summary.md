> 汇总产物 · plan 流水线收口

## 一、这份规划在做什么

为 `dskts` 建一套结构化 Code Wiki（**索引 + 9 个章节文件**，纯 Markdown），让未读过源码的新读者或其他 Agent 能在文档内建立完整心智模型：它是什么、怎么跑、由哪些模块组成、关键函数各自负责什么、模块间如何依赖、改哪里会牵动哪里。

**规划止于文档形态**：本流水线只产出规划件，不写 Wiki 正文。

### 速读测试修出的问题（均已修复）

1. **退出码表述与实现不符**——01 原写「三档可分：答完了 / 可能截断 / 没做成」，但截断与失败实际都是退出码 1。改为按实际契约表述，并新增 [09](./09-验证体系与技术债.md) 技术债第 8 条。
2. **「四种终态」前后不一致**——02 依据表写四种、正文写三种。统一为「声明四种、产出三种」。
3. **「一拍」一词两种含义**——判定采样间隔与日志轮询频率共用。拆开表述。
4. **术语未定义**——「稳定」是否逐字相同、`busy` 与停止按钮的关系、「环境特征」指什么。均补定义。
5. **文档违反自定规则**——02 术语表复述了端口与采样间隔数值，与「不复述常量数值」的约定冲突。去数值并收紧约定措辞。
6. **退出码记号易误读**——02 附件失败写成「退出码 2 / 1」。拆为两种情形分别标注。
7. **性能数字缺限定**——「热连接约 3 秒」未说明不含模型生成耗时。已补注。
8. **匹配规则描述不准**——08 原写「按进程标记与 profile 名精确匹配」，实际是「进程名 + 命令行标记」双重匹配。已改正。
