页面 JS 返回样本

page.py 测试用假 Marionette 返回这些样本，断言解析结果。

DOM 快照

保存侧栏、消息区、菜单等 HTML 到 fixtures/dom/。

如果 page.py 里有 Python 解析逻辑，用 html.parser 离线断言。

坑：标准库不能执行 JS。当前大量逻辑在 JS 字符串里，所以 DOM 快照不能直接跑那些 JS 片段。除非你把部分提取逻辑搬回 Python，否则 DOM 快照只能测纯 Python 文本处理。这一点要明确，不要设计成“离线跑 JS”。

编排回放

保存一次 ask 的完整 Marionette 命令/回包序列。

测试 app.ask() 是否发出预期命令、是否返回正确文本和截断标志。

坑：录制会过时，不能替代真实站点冒烟。

保留 tools/probe_live.py

联网跑真站点，生成或更新 fixtures。

不纳入自动测试。

坑：需要登录 profile，站点改版会失败，必须人工判断是否更新。

测试纪律

fixtures 带日期和来源注释。

不要自动更新 fixtures，否则回归失去意义。

断言行为，不要断言具体 DOM 文本。

测试失败先怀疑站点改版，再怀疑代码。

明确区分：回放测试通过 ≠ 真站点可用；DOM 快照测试通过 ≠ JS 选择器没坏。

不确定点：DOM 快照能否覆盖你现在的 JS 选择器，取决于你是否愿意把“找元素/数出现次数/截取答案”的一部分从 JS 搬回 Python。如果继续全用 js() 执行，标准库无法离线执行这些片段，只能做返回样本回放。
