目标很具体：在终端里向某个网页版 AI 对话工具提问，稳定拿到完整答案，要能带附件、能续接同一会话，并且不把登录凭据复制到临时目录。

我打算这么做：用 Edge 命令行加载一个未打包扩展 → 扩展的内容脚本加一个跑在页面主世界的注入脚本，包住 window.fetch，把网页自己发出的流式响应抄下来 → 通过 Native Messaging host 转发给本地命令行 → 打印答案。

请回答四件事，都要具体到机制，别讲通用原则。

一、这条路有哪些已知的致命坑。逐条说：Chromium 现在还能不能用 --load-extension 加载未打包扩展，企业策略或浏览器版本会不会禁掉；MV3 下内容脚本注入主世界的时机，能不能赶在页面自己保存 fetch 引用之前包住它；service worker 空闲休眠会不会把 Native Messaging 端口断掉、怎么保活；流式响应如果是压缩或分块传输，抄下来的帧能不能可靠重排；扩展 debugger 权限有没有别的办法拿响应体；网站检测扩展环境或 CDP 之后拒绝服务，一般是怎么检的。

二、比起 hook fetch，有没有更稳的拿答案办法。我想到几个，请逐个评：读页面自己写进 IndexedDB 或内存里的会话状态；用 MutationObserver 监听消息容器并配合它自己的 DOM 结构判断结束；用 performance.getEntries 或资源计时判断请求结束；扩展的 debugger API（chrome.debugger）直接读网络响应；以及注入脚本改包 EventSource 或 XMLHttpRequest。哪个最不容易被改版打断，代价分别是什么。

三、在"只用个人账号、不想额外按量付费、偶尔一次人工登录可以接受"这个前提下，这条扩展路线和官方 API 路线相比，哪个更划算？请按维护成本、能力覆盖（网页版独有的联网搜索和智能体能不能拿到）、被封或失效时的恢复代价来判断，不要默认推荐 API。

四、如果你觉得我问偏了或者漏了更关键的问题，直接说该问什么。
