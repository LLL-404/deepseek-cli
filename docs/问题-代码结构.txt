现状：一个 740 行的单文件 Python 脚本 dsk.py，零第三方依赖，只用手写参数解析。它驱动浏览器自动化协议去操作某个网页版对话站点。文件内实际分五块，顺序如下：

1. 常量区：URL、会话名前缀、端口、临时目录路径、要排除的 profile 文件名单，以及十几段内嵌的 JavaScript 字符串（找开关元素、开菜单、重命名、数问题出现次数、截取答案、列会话锚点等）。
2. Marionette 类：TCP 连接、"<字节数>:<json>" 分帧收发、命令数组 [0,id,名,params]、回包 [1,id,error,result]、js() 便捷方法、close() 与 with 支持。协议细节（哪些命令名可用、特殊键 U+E007、GetUrl 与 GetCurrentURL 的区别）只写在这个类的注释里。
3. 环境层：挑火狐 profile（按 moz_cookies 里有无目标域记录判登录态）、复制副本、起独立实例、探测端口、清扫残留、按命令行精确杀进程。
4. 页面操作层：打开会话页、列会话锚点、读与设 aria-pressed 开关、显形隐藏的 file input 并喂附件、按 id 导航、打开行菜单做重命名与删除、等待答案生成（分段：先 30 秒，未完续 30 秒，最多 6 段）、从页面正文里定位答案并清洗（问题文本在页面里会出现多次，靠"提交前先数出现次数、定位第 N+1 次"来锚定，并把输入区工具条那行当结束边界）。
5. 编排层：ask() 把这些串起来（复用或新建会话 → 设开关 → 挂附件 → 填问题 → 提交 → 落地确认 → 等生成 → 改名 → 返回文本与是否截断）；main() 手写解析 up/status/down/chats/rm/--file/--chat/--new/--no-think 等，答案走 stdout、日志走 stderr，退出码目前只有 0 和 4（4 表示可能截断）。
