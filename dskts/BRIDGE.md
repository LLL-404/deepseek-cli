# bridge — 顾问桥 v2：网页 DeepSeek 当总架构师，本地当机械手，state.md 当记忆

2026-10-09 写了 v1（四行协议），同日改成 v2。改的原因不是风格：v1 把 DeepSeek 用成了「下一条命令生成器」，只花它的执行力，不花它的判断力。v2 的分工是——**它定目标、拆阶段、做根因、动态重规划、需要时自己写脚本；本地只读它回复里的两个机器块，块外的思考文字一概不看**。这样它能充分思考，弱执行器又不会被推理绕晕。

这份文档记**实际建成了什么、每条设计被哪一次实测逼出来**。分工方案的评审与逐条判断在 `../docs/评审-顾问桥.md`。

## 快速上手

```
node src/bridge.ts init --goal "要做什么"        # 建 state.md（已存在则拒绝，--force 才覆盖）
node src/bridge.ts ask                          # 发简报 → 顾问回复 → STATE 落 state.md、步骤表打 stdout
node src/bridge.ts act                          # 跑 advice.txt 里那一批（逐步过闸门，失败即停）
node src/bridge.ts act --only 2                 # 只跑第 2 步
node src/bridge.ts act --from 3                 # 从第 3 步接着跑（人自己跑完第 2 步之后用）
node src/bridge.ts apply advice.txt             # 预检表：每步会不会被拦、EXPECT 能不能判，一步不跑
node src/bridge.ts run --rounds 12              # ask+act 循环
```

半自动（人当信使，不让程序碰网页）：`ask --emit ask.txt` 只产简报；人贴进网页，回复存成 `advice.txt`；`apply` 看预检；`act` 执行。

`--state` 换状态文件，`--max-wait` 换顾问等待上限（默认 240 秒），`--rounds` 换循环上限（默认 12）。

## 协议：思考文字 + 两个标记块

顾问每轮的回复长这样（执行器只读方括号里的那两段）：

```
[[STATE]]
阶段：…
目标：…
成功标准：…
已完成：…
待办：…
关键决策：…
未决问题：…
[[/STATE]]

[[EXEC]]
STEP: 1
ACTION: shell
CMD: python --version && echo __R1_OK__
EXPECT: 包含:__R1_OK__
ON_FAIL: 回报完整 stderr 与退出码
DANGER: no
STEP: 2
…
[[/EXEC]]

## 形势判断 …（执行器不看）
```

动作词表：`shell / python / read_file / write_file / ask_user / done`。一轮最多 **8 步**，超了**整批拒**（静默截断会跑出「顾问没打算一起跑的组合」）。缺 EXEC 合法（它这轮只想更新记忆），缺 STATE 报错（记忆断了要当场知道）。

这些形状不是审美选择，是被这条传输一条条逼出来的。每条都有对应测试：

| 规矩 | 实测依据 |
|---|---|
| 分隔用 `[[STATE]]` 标记，不用 ``` 围栏 | 围栏与语言标记那两行**在 DOM 里根本不存在**（探针：要求写 ```STATE 包住一行 `阶段：探针`，回来只剩那一行）。按围栏找块永远找不到。 |
| 步与步靠 `STEP:` 行切，不用 `---` | `---` 被渲染成分隔线后同样消失。实弹：四步回复被读成一步，`ACTION` 取到「write_file\npython\nread_file\ndone」。 |
| 机器块放**最前面**，分析写短 | 实弹一条写了 1700 字分析的回复被站点从中间截断，执行包切在 STEP 1 的 CMD 上。 |
| 要缩进的脚本，在标记里再包一层代码块 | 段落渲染会折叠行首空白：顾问第一次写的 python 脚本回来全是顶格，`IndentationError`。代码块里的缩进实测能活着回来（探针要求第 3、4 行各 4 空格，回来的 JSON 里空格在），最后一轮真跑出了带四级缩进的脚本。 |
| 判成败用 `&& echo __哨兵__` + `包含:哨兵` | `命令 & echo __OK__` 在命令**失败时**照样打印哨兵，且整行退出码 0；`%ERRORLEVEL%` 在单行里是解析期展开，读到的是这一行开始前的值。五条对照见 `tools/probe_cmd_sentinel.mjs`。 |

**EXPECT 只认五种机械形式**：`exit=N`／`退出码 N`／`包含:X`／`不含:X`／`regex:X`／`非空`。写成散文（「应该列出文件名」）判 **未判定**，与失败一样**立即停批**——把散文交给弱模型判，它会把任何输出读成满足；而不可判定往往就是编码、CRLF、吞行这类会连续复现的字节问题，放过去就是基于错假设继续动手。

## state.md：两个区，一个整块覆盖、一个只追加

```
# 任务状态
目标：…          环境：…          当前状态：…

## 顾问记忆          ← 每轮由顾问的 STATE 整块覆盖（滚动记忆）
- 阶段：…  - 目标：…  - 成功标准：…  - 已完成：…  - 待办：…  - 关键决策：…  - 未决问题：…

## 轮次记录          ← 只追加，每步一条，跑完立刻写穿
### 第 1 轮 步骤 2/3
- STEP: 2
- ACTION: python
- CMD: _c1.py
- EXPECT: 包含:R2_OK
- 结果: 失败（退出码 1）
- 输出摘要: IndentationError: expected an indented block …
```

写入是原子的（先 `.tmp` 再 rename）：DeepSeek 在那轮问答里点出「弱执行器只会 writeFile，写一半断掉就静默丢整轮记忆」。本仓复测 `fs.renameSync` 在 Windows 上能覆盖已存在的目标，这条路可用。

简报只带**最近 3 轮**，且带压缩策略：`阶段/目标/成功标准/未决问题` 各留 300 字，`已完成/待办/关键决策` 折叠成「共 N 项，只列最近 6 项」；折叠完还超 6000 字就**报错**，不静默截断（外发内容必须可控）。上一轮为什么没走下去（不合规／没给 EXEC／停在哪一步）会写进下一轮简报的「当前输出/错误」——顾问只看简报，不告诉它就等于让它盲规划。

## 闸门：三道，代码级，没有任何参数能关掉

1. **危险动作要人**：`stepGate` = 顾问声明 `DANGER: yes` **或** 本地扫描命中，取并集，两边都说安全才放行。**扫描器按动作分**——这是实弹撞出来的：`write_file` 的脚本内容里有 `if os.path.getsize(f) > 50 * 1024 * 1024:`，按 shell 的重定向规则被判成「覆盖已有文件」，第一步就拦停，等于把「顾问写脚本、本地只跑脚本」这条主路堵死。所以 `shell` 用命令语法扫（删除/格盘/覆盖/支付/外发/装软件/改系统/杀进程/丢工作区），`python` 用代码语法扫（`os.remove`、`open(...,'w')`、`shutil.move`、`subprocess`…），`write_file` **只看路径行**（内容是数据，不是命令）。
   命中就停：TTY 里逐步问人（默认 No），非 TTY 直接退 2 并打印「要跑就人工自己跑这一步，再 `act --from k+1` 接着走」。误拦两次也修过：`2>nul`、`>/dev/null`、`2>&1` 都不是覆盖。
2. **工作目录围栏**：`read_file`／`write_file`／`python`（路径形式）只许碰工作目录里面的东西（`withinDir`，绝对路径与 `..` 一律拒）。`read_file` 读到的内容下一轮会随简报外发，不设围栏就是「读盘即外泄」通道。`write_file` 还额外拒绝：目标已存在（覆盖要人做）、以及 `state.md`／`advice.txt`／`ask.txt`（顾问不能改执行器的账本）。
3. **输出上限 256KB + 120 秒超时**：超限杀命令并截断。来自真实事故——Git 的 `/usr/bin` 在 PATH 里排在 System32 前面，顾问给的 `find /c /v ""` 解析成 **GNU find**，把 `/c` 当成 `C:\` 递归整个 C 盘，一次产出 132,258,887 字。对策两条：`cmd.exe` 路线把 System32 提到 PATH 最前（`cmdEnv()`），以及无论谁跑都有上限（`capOutput()`）。

闸门是关键词级的，**不是沙箱**：`shell` 拿到真 shell。真正的边界是每步都落 `state.md`、危险家族一律交回给人。

## 传输：全部经 dskts，桥自己不碰浏览器

简报走 **stdin** 灌给 `dskts`（`--mark Bridge --out <临时文件>`），答案从 `--out` 落盘文件读不读 stdout（终端回显会整段丢行）。顾问会话是 `Bridge｜连续会话`，不蹭 Qoder 的连续会话。顾问的系统提示**每轮随简报重发**——「上下文不互通」是这套设计的前提，不是缺陷。凭据一律不经桥。

## 退出码与循环判据

`0` 正常（含顾问判定 done）／`1` 运行错误（不守格式、命令失败、未判定、输出超限）／`2` 需要人（危险步骤、`ask_user`、被围栏拒绝、没有 state.md）。

停止判据是纯函数：`loopDecision(RoundResult)`——done 收工返 0；待人／不合规 交回给人；**批内失败与未判定都不停轮**，下一轮把错误带给顾问（v1 实测过反面：done 返 0 而循环只在 2 时停，于是空转三轮问出三个 done）。批内则是**任一步失败即停批**，后面的步一步都不跑。

## 与作者规格的逐条对照

| 规格要素 | 状态 | 说明 |
|---|---|---|
| 顾问自由思考，本地只读机器块 | ✅ | `extractBlock` 只取两个标记块，块外一概不读 |
| STATE 块（阶段/目标/成功标准/已完成/待办/关键决策/未决问题） | ✅ | 七字段全量重写、整块覆盖 |
| EXEC 多步块 | ✅ | 六字段一步一条，上限 8 步，超了整批拒 |
| 本地按 STEP 顺序执行、原样执行不改写 | ✅ | `runSteps`，每步写穿 state.md |
| 每步查 DANGER，yes 先问人 | ✅ | 且**叠加**本地关键词扫描，声明 no 不降级 |
| 执行后检查 EXPECT | ✅ | 五种机械形式；判不了的「未判定」= 停批回报 |
| 失败即停，生成失败简报再问 | ✅ | 停批 + 原因（含 ON_FAIL 与输出）进下一轮简报 |
| 复杂命令让顾问写脚本、本地只跑脚本 | ✅ | `write_file` + `python`（v1 做不到，只能 `>` 重定向，每轮撞覆盖闸门） |
| `state.md` 外部记忆 | ✅ | 两区；v1 的文件仍读得动 |
| 半自动 `ask.txt` / `advice.txt` | ✅ | `ask --emit` + `apply` + `act --advice` |
| `goal.md` / `plan.md` / `decisions.md` / `logs/` 四个文件 | ❌ 刻意合并 | 头部=契约、顾问记忆区=plan+decisions、轮次记录=log 摘要。同一份事实抄四处正是作者判「乱」的地方 |
| `write_file` 之外的 `browser_*`／`screenshot` | ❌ 刻意不做 | 桥摸不到 keeper 里的 page；列进词表就违反规格自己的防呆第 3 条 |
| 非变更动作也标 `DANGER`（两根轴分开） | ❌ 不改 | 作者规格把字段钉死成 `DANGER: no\|yes`，改名会让执行器与规格对不上。评审里这条建议记录在案 |
| `ask_advisor()` / `execute()` 两个 MCP 工具 | ❌ 暂缓 | 执行器若是 Qoder 系，直接调本 CLI 即可；换宿主再说 |

## 验证记录

**离线**（`node tests/bridge.test.ts`）：**64 项全绿**；`npx tsc --noEmit` 干净；五套合计 **104 项**（judge 14 / frame 7 / agent 16 / bridge 64 / env 3）。
**变异自检**：`node tools/mutate_bridge.mjs` —— **15 个变异逐个变红**，`NOT-DISCRIMINATED = none`，还原后全绿。清单：闸门只信声明／只信扫描／write_file 拿整段内容扫 shell 规则／python 走 shell 规则／未判定当满足／步数静默截断／STATE 改追加／k-of 往返取错行／简报带全部历史／两道围栏各拆一次／done 不停轮／标记被忽略／同标记两块静默取第一个／散文 EXPECT 当满足。
**实弹（2026-10-09，临时目录，真问网页 DeepSeek）**：
- 反证四条（手工喂回复）：两步连跑 rc=0 且哨兵判「满足」；第 2 步 `process.exit(3)` → 第 3 步的 `marker.txt` 没被创建；散文式 EXPECT → 「未判定即停」；`DANGER: no` + `del /q victim.txt` → 已拦、退 2、文件还在。
- 第一轮撞出两个协议 bug（围栏、`---`），改完再跑：一次 `run` 里三步全跑、`done` 收工、`report.md` 行数正确，落地的脚本**保留着四级缩进**。
- 失败重规划真发生过：顾问第一轮的脚本 `IndentationError` → 停批把原样错误带回 → 第二轮它改成顶格语句自己绕过去；再一轮用上代码块包缩进，一次通过。

## 已知边界

- **顾问可能不守格式或被截断**：连续两轮拿不到合规回复，`run` 就停，不在坏格式上空转。被截断的回复（有 STATE 无 EXEC）落成 0 步并回灌下一轮简报。
- **`write_file` 内容如果正好以一行 ``` 结尾**，会被 `stripFenceEdges` 削掉最后一行。只削首尾各一行，中间的不动。
- **非 TTY 宿主没法在流中问人**：读到一半会挂死整轮，所以直接退 2 交回给人。
- **闸门按关键词判**，改写法能绕（把删除写成别的调用形式）。评审给的更硬做法里，「可执行文件白名单」等于换掉工具用途、「shell 行路径强制」误拦率会把工具废掉、「变更前快照」是另一个功能——都写明了不做，理由见 `../docs/评审-顾问桥.md`。
- `cmd.exe` 是默认 shell，简报会告诉顾问实际用的是哪个；`BRIDGE_SHELL=bash|powershell` 可换。
- `python` 动作要求机器上有 `python`，没有就报「起不来」，不会静默成功。
