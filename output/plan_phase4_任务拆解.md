# Phase 4 任务拆解：dskts

写于 2026-10-06。基于 [Phase 3 技术规格](plan_phase3_技术规格.md)。工时为专注开发的净工时（真页面验证类任务另计机器等待）；「验收挂钩」指向 [Phase 2 PRD](plan_phase2_PRD.md) 第 5 节。

## 执行顺序总览（里程碑制，M0 是全计划闸门）

```
M0 Gate 风控验证 ──过──► M1 P0 问答链路 ──► M2 P1 会话管理 ──► M3 P2 补齐升级 ──► M4 观察期与退役
      │                                                                              
      └─失败─► T0.4 重出 Selenium 备选规格（回到 Phase 3）
```

并行点：T1.4（judge 纯函数）不依赖任何浏览器代码，可与 T1.2/T1.3 并行；M4 观察期（日历 7 天）与 M2/M3 开发并行推进。

## 汇总

- **开发净工时**：M0 ≈ 3h，M1 ≈ 11~13h，M2 ≈ 2h，M3 ≈ 4.5~7h，合计 **约 21~25h**（Gate 失败分支 +4h，cookie 导入 +2h 可选）。
- **日历时间**：开发可压缩在 3~4 个工作日内；M4 观察期固定 7 天与 M2/M3 并行。
- **关键路径**：T0.3 Gate → T1.3 env → T1.6 提问链路 → T1.7 编排 → T1.8 验收。
- **回退点**：仅一个——T0.3 Gate 失败回 Phase 3 换 Selenium；此后各里程碑只有"修到过验收"，无路线级回退。
