# Phase 2 PRD：DeepSeek命令行 TS 版

写于 2026-10-06。基于 [Phase 1 需求梳理](plan_phase1_需求梳理.md)，四个分叉已确认。

## 1. 产品概述与背景

**一句话**：用 TypeScript + Playwright 重建 DeepSeek 网页版命令行工具（过渡期命令名 `dskts`，退役 Python 版后接管 `dsk`）：能力全量对齐，凭据从「每次复制副本」改为「常驻持久 profile」，并为拿到结构化响应流（正文/思考/结束原因）铺路。

**背景**：

- 现版 `dsk`（Python 857 行、零依赖）已可用：复制 Firefox profile 继承登录态 → `--marionette` 起独立实例 → 手写协议驱动 chat.deepseek.com → DOM 取词出答案。2026-10-05 刚完成一轮等待判定加固（busy 门 + 读数抖动容错 + `--max-wait`）。
- 三个结构性局限（DESIGN-dsk2.md 已认定）：① 凭据副本落盘、强杀/断电残留；② 答案靠 DOM 猜，页面改版即失；③ 冷启动约 30 秒且单实例单连接。
- 2026-10-06 决策：解除第三方库禁令、全面换装 TS。四项分叉确认结果：驱动=Playwright（Firefox 持久 profile）；旧 Python 版保留为后备；dsk2 扩展路线搁置、文档保留；范围=全量对齐。

**与现版的关系**：dskts 是重写不是逐行移植——协议层与等待状态机被 Playwright 替换或大幅简化，但 DOM 取词逻辑仍要跟随页面结构（这部分经验平移）。硬规则原样生效（见第 4 节）。

## 3. 功能详述

### P0

**F0 风控一锤子验证（Gate，先于一切功能开发）**

- 做法：dskts 最小骨架（Playwright + persistent context，有头）指向 chat.deepseek.com，用户手动登录一次，连续 ≥10 次真实问答（含深度思考+搜索双开）。
- 过关判据：登录无验证码墙；全部问答出完整答案；无账号风控警告；DOM 取词容器（`.ds-assistant-message-main-content`）在新浏览器里行为与现版一致。
- 失败处理：整条 Playwright 路线退回备选（Selenium + 原版 Firefox + profile 副本模型），回 Phase 3 重出技术方案；其余需求不变。

**F1 环境建立与生命周期**

- profile 目录：`%LOCALAPPDATA%\dsk-ffprofile`，常驻（不再是每次的临时副本；与旧 `dsk-ffcopy` 互不影响）。
- `up`：起 persistent context（有头），校验登录态；未登录时明确提示「去窗口里登录一次」，登录完成后自动继续。
- `down`：关实例 + 整目录删除（含全部登录态）。从旧版的「用完必删义务」变为「显式一键清除」。
- `status`：实例在否、登录态、profile 目录状态。
- 崩溃残留清扫：启动前清陈实例与锁文件（对齐现版 `sweep_stale` 语义）。
- 单实例：已有实例直接复用连接（不复制 profile）；两终端并发时明确报「忙」——升级点，现版会互相掐断。

**F2 提问链路（核心）**

- 会话选择：默认续用最近带 `qoder｜` 前缀的会话；找不到则新开对话，答完后改名打前缀。
- 开关：深度思考、智能搜索默认全开，已是目标值不重复点（对齐现版 `set_toggle` 语义）。
- 填题回读校验逐字一致，不等中止（防半截提交，沿用现版铁律）。
- 提交前验前提：页面有停止按钮（上一条在生成）→ 退出码 2 + 明确报错，不提交。
- 完成判定双信号：文本稳定 N 拍 **且** 停止按钮消失；`--max-wait`（默认 240 秒）为总上限，到点返回已得文本并标注「可能被截断」（退出码 1）。分段续期机制是否保留由 Playwright 的 auto-wait 能力决定，Phase 3 定。
- 取词：答案正文容器选择器平移（`.ds-assistant-message-main-content`，代码块横幅先隐藏）；取不到容器时报「页面改版」并带证据，绝不给空答案。

**F3 CLI 面（与 Python 版对齐）**

- 主命令：`dskts "问题" [--chat 关键词] [--out 文件] [--mark 前缀] [--max-wait 秒] [--file 路径]…`
- 子命令：`up` / `down` / `status` / `chats` / `rm`（支持 `--any`）。
- stdout 永远只有答案；过程日志全在 stderr，带时间戳（沿用现版风格）。
- 退出码三档：0 成功；1 运行错误（含超时截断返回）；2 前提不满足（未登录、生成中、`--chat` 命中不唯一等）。

### P1

**F4 chats**：列出全部会话（标题 + id），带 `qoder｜` 前缀的排前。
**F5 --chat 续问**：关键词匹配，命中 0 条或多条 → 拒绝并列出候选（退出码 2），唯一命中才进。
**F6 rename / rm 白名单**：改名打前缀（F2 内含）；`rm` 只删 `qoder｜`（或 `--mark` 自定义前缀）会话，无前缀一律拒绝，`--any` 显式越过。硬规则，无例外路径。

### P2

**F7 附件**：`--file`，扩展名白名单对齐现版；上传后轮询文件名出现在页面（最多 20 秒）。
**F8 离线测试**：完成判定状态机注入假读数（对齐现 14 项测试思路）；CLI 解析与退出码映射；mock 页面的 Playwright 冒烟测试。
**F9 流式终端输出**：若 Playwright(Firefox) 能增量读响应流 → 边生成边打印（首字 ≤5 秒）；只能拿全量 → 维持整段返回，文档写明能力边界。
**F10 probe 诊断工具**：TS 化，报容器条数、busy 状态、横幅隐藏前后字数、读数确定性。

## 4. 非功能需求

**性能**

- 冷启动（起浏览器→可提问）≤ 15 秒（现约 30 秒，主要省掉 profile 复制）。
- 热连接（实例已起）≤ 3 秒。

**安全（硬规则，任何阶段不可违反）**

1. 不伪造 `bf`、`dltk` 这类反爬令牌；不在浏览器之外重放会话凭据——驱动真浏览器、由页面自己签名。
2. `rm` 只认 `qoder｜` 前缀会话，`--any` 才能越过。
3. 不往外发正文和未公开设定；报错只带工具用法、错误原文、通用技术信息。
4. 登录态只存在于 profile 目录；`down` 必须能整体删除且删后需重新登录；stdout/stderr 不输出 cookie、令牌。

**兼容**

- Windows 10/11；Node ≥ 24 LTS（原生跑可擦除语法的 .ts）；Playwright 自带 Firefox，版本锁进 lockfile；不要求系统安装 Firefox。

**可维护**

- TypeScript strict；模块分层沿用 DESIGN.md 的「只该知道/不该知道」纪律（环境层/页面层/编排层互不越界）；页面选择器集中在单文件常量区。

**可观测**

- stderr 时间戳日志；等待判定过程（稳定拍数、busy 状态、超时续期）可见。

## 5. 验收标准

**Gate（F0）**：按 F0 判据，全计划第一道闸，不过则切备选路线。

**P0 验收**：

1. 全新场景：`dskts up` → 窗口登录一次 → `dskts "你好"` stdout 出答案、退出码 0、stderr 有过程日志。
2. 多轮：连续两次提问进同一会话，第二次利用了第一次的上下文。
3. 截断路径：`--max-wait 10` 问长题 → 退出码 1、明示「可能被截断」。
4. 前提路径：上一条生成中再发 → 退出码 2、不提交。
5. 安全路径：`dskts down` 后 profile 目录不存在，再 `up` 需重新登录。
6. 兼容抽查：`--out` 落盘内容与 stdout 逐字一致；`--chat` 多命中拒绝并列候选；`--max-wait 0`、`--max-wait abc` 报参数错。
7. 参数面与 Python 版对照表逐项核对全绿。

**P1 验收**：`chats` 列全且前缀会话排前；`rm` 拒绝非前缀会话、`--any` 才删；改名后标题带前缀。

**P2 验收**：附件文件名出现在页面；离线测试套件不起浏览器全绿；（若做流式）首字上屏 ≤5 秒且最终全文与整段模式逐字一致。

**退役判据（Python 版）**：dskts 真实使用一周、≥20 次问答、0 次「答案残缺但退出码 0」、≥3 次删除演练正确 → Python 版标记退役，`dsk` 命令名移交 dskts，DESIGN.md 与 README 同步改写。
